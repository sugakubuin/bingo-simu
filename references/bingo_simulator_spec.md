# ビンゴ捲り期待値シミュレーター 仕様書

最終更新: 2026-08-13
準拠ルール: 二向聴 チューリップ公式ルール（2026/8/2 更新）

---

## 0. 概要

和了牌姿・花牌の抜き枚数・残り牌山の長さなどを入力すると、その条件下でツモ山を
100,000 パターン生成し、各山でチューリップをめくり切ったときの祝儀枚数を集計して
期待値および分布を表示する、ブラウザ完結型の Web アプリケーション。

対象は **ウルトラビンゴ** と **スーパービンゴ** の 2 モード。

---

## 1. 用語と基本ルール

### 1.1 チューリップ

和了時にツモ山の**上段**をドラ表示牌側から順に 1 幢（トン）ずつめくる。めくった牌
とその前後の牌が手牌（＋抜き牌）に含まれていた場合、その枚数だけ祝儀がのる。
1 枚ものらなかった時点で終了。のる限り山の端までめくり続ける。

### 1.2 確変

確変状態では上段に加え**下段**もめくれる。上下どちらものらなかった時点で終了。

### 1.3 突確

**1 枚のめくり**で 6 枚以上のったとき突確に入る。上下合計で 6 枚は突確にならない。
突確に入ると**次のトンから**確変状態になる。

### 1.4 16R

以下のいずれかで 16R（確変の上位状態）に入る。

- 手牌が「777 の 777」（7p が 3 枚以上 **かつ** 7s が 3 枚以上）
- 確変状態中に突確に入ったとき

16R では**終了時の合計枚数が 2 倍**になる。条件が重複しても 2 倍のまま（上限あり）。

### 1.5 転落保証

一発・白ポッチ・三倍満以上の和了に付く。0 枚のトンでこれを 1 個消費して終了を
スキップできる。複数個持っていれば連続して消費できる。

## 2. 牌構成

三人麻雀セット（108 枚）が基準。萬子は 1m・9m のみ 4 枚ずつ。

### 2.1 ウルトラビンゴ（計 108 枚）

| 種別 | 内訳 | 枚数 |
|---|---|---|
| 萬子 | 7m ×4 | 4 |
| 筒子 | 1p–9p 各 4 | 36 |
| 索子 | 1s–9s 各 4 | 36 |
| 字牌 | 東南西北白發中 各 4 | 28 |
| 花牌 | ×4 | 4 |
| **合計** | | **108** |

- 1m・9m を除き、代わりに 7m を 4 枚入れる。
- 山からめくれた 7m は 7p / 7s の好きな方として扱える。

### 2.2 スーパービンゴ（計 112 枚）

| 種別 | 内訳 | 枚数 |
|---|---|---|
| 萬子 | なし | 0 |
| 筒子 | 7p ×8、他 各 4 | 40 |
| 索子 | 7s ×8、他 各 4 | 40 |
| 字牌 | 東南西北白發中 各 4 | 28 |
| 花牌 | ×4 | 4 |
| **合計** | | **112** |

- 萬子は一切入らない。7p・7s のみ 8 枚ずつ。

## 3. のり判定

### 3.1 循環構造

牌は**循環**している。めくり牌 `X` に対し、`prev(X)`, `X`, `next(X)` が判定対象。

| グループ | 循環 |
|---|---|
| 筒子 | 1p → 2p → … → 9p → 1p |
| 索子 | 1s → 2s → … → 9s → 1s |
| 風牌 | 東 → 南 → 西 → 北 → 東 |
| 三元牌 | 白 → 發 → 中 → 白 |

例:

- 1p がめくれる → 手牌の **9p, 1p, 2p** の総枚数がのる
- 9s がめくれる → 手牌の **8s, 9s, 1s** の総枚数がのる
- 西がめくれる → 手牌の **南, 西, 北** の総枚数がのる
- 白がめくれる → 手牌の **白, 發, 中** すべての総枚数がのる（3 枚循環のため）

### 3.2 花牌

- 花牌がめくれたとき、のり枚数 = **(抜いている花牌の枚数) × 3**
  - 0 枚抜き → 0 枚（＝終了扱い）
  - 1 枚抜き → 3 枚、2 枚抜き → 6 枚、3 枚 → 9 枚、4 枚 → 12 枚
- **花牌は数牌・字牌のめくりでは一切のらない**。花牌がめくれたときのみカウントする。
- 抜いた花牌は山から減るので、**山に残る花牌は $4 - f$ 枚**（$f$ は抜き枚数）。

#### 花牌と突確

| モード | 挙動 |
|---|---|
| ウルトラ | 花牌で 6 枚以上のれば通常どおり突確に入る（2 枚以上抜きが該当） |
| スーパー | **花牌では突確に入らない**。9 枚・12 枚のっても状態遷移なし |

### 3.3 ウルトラビンゴの 7m

山からめくれた 7m は、**そののり枚数が大きくなる方**（7p 見立て / 7s 見立て）を
自動選択する。

```
nori(7m) = max( nori(7p), nori(7s) )
         = max( count(6p)+count(7p)+count(8p),
                count(6s)+count(7s)+count(8s) )
```

手牌側に 7m は存在しない（入力前に 7p / 7s へ読み替え済み）。

### 3.4 その他

- 手牌の牌は毎回のめくりで**再利用される**（同じ牌が何度でもカウントされる）。
- 槓子は 4 枚としてカウントする。暗槓・明槓・加槓の区別はしない。
- 刻子の副露有無はのり枚数に影響しないため入力しない。
- 赤 5 は通常の 5 として扱う（入力上も黒 5 のみ）。
- 白ポッチは入力前にプレイヤーが読み替え済みとし、専用の入力は設けない。

## 4. 入力仕様

| 項目 | 型 | 範囲・既定値 | 備考 |
|---|---|---|---|
| モード | 選択 | ウルトラ / スーパー | 既定: ウルトラ |
| 和了種別 | 選択 | 通常手 / リーチなし役満 / リーチ役満・天地人和 | 既定: 通常手 |
| 面前手牌 | 牌姿 | $14 - 3k$ 枚 | $k$ は槓子数 |
| 槓子 | 牌 × $k$ 組 | $k = 0 \ldots 4$ | 1 組につき 1 種を指定 |
| 花牌抜き枚数 | 整数 | 0 – 4、既定 0 | |
| 残りトン数 $N$ | 整数 | 1 – 30、既定 20 | 10 / 20 / 30 のクイックボタン併設 |
| 転落保証 | 整数 | 0 – 3、既定 0 | |

### 4.1 牌姿の入力方式

**両対応**とする。

1. **牌クリック入力**: 牌画ボタンを並べ、タップで追加 / 削除。
2. **テキスト入力**: 標準的な牌譜記法（例 `東東東23456p7765s`）。
   - 双方向同期し、どちらを編集しても他方に反映する。
   - 槓子は別枠で指定する。

### 4.2 選択可能な牌

| モード | 選択肢 |
|---|---|
| ウルトラ | 1p–9p, 1s–9s, 東南西北白發中 |
| スーパー | 1p–9p, 1s–9s, 東南西北白發中 |

いずれのモードでも**萬子（7m を含む）は選択肢に出さない**。

### 4.3 バリデーション

- 同一牌種は手牌全体（面前＋槓子）で最大 **4 枚**。7p・7s も 4 枚まで。
- 面前部分の枚数はちょうど $14 - 3k$ 枚。
- 手牌の総枚数は $14 + k$ 枚（＋花牌 $f$ 枚は別管理）。
- 和了形（4 面子 1 雀頭）の検証は**行わない**。
- 山の生成に必要な $2N$ 枚が残り牌から確保できること。
  - ウルトラ: $2N \le 108 - (14 + k) - f$
  - スーパー: $2N \le 112 - (14 + k) - f$
  - $N \le 30$、$k \le 4$、$f \le 4$ のとき常に成立する。

## 5. 初期状態の決定

手牌（面前＋槓子）から以下を判定する。

- **777 条件**: 同色の 7 が 3 枚以上（7p が 3 枚以上、または 7s が 3 枚以上）
- **777 の 777 条件**: 7p が 3 枚以上 **かつ** 7s が 3 枚以上

| 和了種別 | 777 の 777 | 777 のみ | いずれも該当せず |
|---|---|---|---|
| 通常手 | 16R | 確変 | 通常 |
| リーチなし役満 | 16R | 確変 | 通常 |
| リーチ役満・天地人和 | 16R | 確変 | **確変** |

> 補足: 「通常手」と「リーチなし役満」はシミュレーション上の挙動が完全に一致するが、
> ユーザーの迷いを減らすため入力選択肢としては分けておく。

## 6. 確率モデル

### 6.1 残り牌山の生成

1. モードに応じた全牌集合（多重集合）を用意する。
2. そこから**手牌（面前＋槓子）** と **抜いた花牌 $f$ 枚**を取り除く。これが未知牌プール。
3. 未知牌プールから一様ランダムに $2N$ 枚を非復元抽出し、順に
   （1 トン目上段、1 トン目下段、2 トン目上段、…）と割り当てる。

他家の手牌・河・ドラ表示牌・王牌はすべて未知牌プールに含める近似を取る。
**河の情報は無視する**。

### 6.2 試行回数

**100,000 回固定**。

---

## 7. シミュレーションアルゴリズム

### 7.1 のり枚数テーブルの事前計算

のり枚数は手牌のみで決まり、山の内容に依存しないため、試行前に一度だけ
テーブル化する。

```
noriTable[kind] を全牌種について計算:

  数牌 / 字牌 X:
      noriTable[X] = hand[prev(X)] + hand[X] + hand[next(X)]
  花牌:
      noriTable[花] = 3 * f
  7m（ウルトラのみ）:
      noriTable[7m] = max(noriTable[7p], noriTable[7s])
```

これにより 1 回のめくりは配列参照 1 回で済む。

### 7.2 1 試行の手続き

```
入力: wall[0 .. 2N-1]（生成済み）, 初期状態(kakuhen, is16R), guard（転落保証数）

total   = 0
tonUsed = 0
pendingKakuhen = false
everKakuhen = kakuhen
everTotsukaku = false

for i = 1 .. N:
    if pendingKakuhen:
        kakuhen = true
        pendingKakuhen = false
        everKakuhen = true

    tonUsed = i

    upper = wall[2(i-1)]
    cU = noriTable[upper]

    if kakuhen:
        lower = wall[2(i-1)+1]
        cL = noriTable[lower]
    else:
        cL = 0

    total += cU + cL

    # --- 突確判定（各めくりを個別に評価）---
    for (tile, c) in [(upper, cU)] + ([(lower, cL)] if kakuhen else []):
        if c >= 6 and not (mode == SUPER and tile == 花牌):
            everTotsukaku = true
            if kakuhen:
                is16R = true          # 確変中の突確 → 16R
            else:
                pendingKakuhen = true # 次のトンから確変

    # --- 終了判定 ---
    if cU + cL == 0:
        if guard > 0:
            guard -= 1
            continue              # 転落保証で 1 度スキップ
        else:
            break                 # 終了

# end for（i == N まで到達したら山の端で強制終了）

if is16R:
    total *= 2

return (total, tonUsed, everKakuhen, everTotsukaku, is16R)
```

### 7.3 実装上の注意

- 突確でもらえる枚数はその回ののり枚数そのまま。追加ボーナスはない。
- 突確が発生したトンの下段はめくらない（非確変だった場合）。確変は**次のトンから**。
- 上段・下段の両方で 6 枚以上のっても 16R は 1 段階まで。
- 16R の 2 倍はチューリップ由来の枚数のみに掛かる。一発・裏・赤・本役満などの祝儀は
  本シミュレーターの計算対象外。
- 転落保証は 0 枚のトンごとに 1 個ずつ消費し、連続消費を許す。

## 8. 出力仕様

### 8.1 サマリー

- **期待値**（平均枚数）
- **中央値**
- **標準偏差**
- **0 枚率**

### 8.2 状態関連

- **初期状態**（通常 / 確変 / 16R）: 入力から決まるためバッジ表示
- **確変到達率**（初期確変を含め、一度でも確変状態になった割合）
- **突確突入率**
- **16R 到達率**
- **平均めくりトン数**（何トン目で止まったか）

### 8.3 分布

- **ヒストグラム**: 枚数ごとの度数。裾が長いのでビン幅は自動調整、または上位を
  まとめた「n 枚以上」ビンを設ける。
- **累積分布**: 「$n$ 枚以上のる確率」の表またはグラフ。
  代表点として 1, 3, 5, 10, 20, 30, 50 枚以上などを表形式でも併記する。

### 8.4 補助表示

- 事前計算した **のり枚数テーブル**（どの牌がめくれたら何枚のるか）を一覧表示すると
  デバッグにも実用にも役立つため、折りたたみで表示する。

## 9. 技術仕様

| 項目 | 内容 |
|---|---|
| 構成 | フロントエンド完結、バックエンドなし |
| 言語 / FW | React + TypeScript |
| スタイル | Tailwind CSS |
| グラフ | Recharts |
| 実行環境 | モダンブラウザ、**スマートフォン対応必須** |
| 永続化 | なし（ブラウザストレージ不使用） |

### 9.1 パフォーマンス

- 100,000 試行 × 最大 30 トン × 2 めくり ≒ 600 万回の配列参照。
- のり枚数テーブルの事前計算により、1 めくりあたりの処理は定数時間。
- 山生成は未知牌プール（約 90–95 枚）に対する部分 Fisher–Yates シャッフルで
  先頭 $2N$ 枚のみを確定させる。
- 想定実行時間は 1 秒未満。UI ブロックが気になる場合は計算中インジケータを出す。

### 9.2 UI 構成

1. モード切替（ウルトラ / スーパー）
2. 和了種別の選択
3. 牌姿入力（牌クリック + テキスト、双方向同期）
4. 槓子入力
5. 花牌抜き枚数、残りトン数、転落保証
6. 実行ボタン
7. 結果表示（サマリー → 状態 → 分布 → のり枚数テーブル）

モバイルでは 1 カラム縦積み、牌ボタンはタップしやすいサイズを確保する。
